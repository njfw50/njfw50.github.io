O Código Canônico de Engenharia & IA é um projeto de Michel Silva de Souza, publicado também como The Canonical Protocol of Engineering & AI. IA é a sigla em português para inteligência artificial; AI é a sigla em inglês usada no endereço do repositório. Seu corpo documental reúne governança de software, arquitetura, segurança, experiência do usuário e o trabalho com assistentes de IA.

O projeto apresenta a Anotação Cognitiva Litúrgica (Liturgical Cognitive Annotation) e discute dívida cognitiva: a perda de compreensão do sistema durante o desenvolvimento assistido por IA. Os textos originais, as propostas e o histórico estão disponíveis no repositório público.

Este é um framework de governança para desenvolvimento de software assistido por IA. Ele propõe registrar decisões, revisar limites arquiteturais e tornar a proveniência do código rastreável. A aplicação depende do contexto e das evidências de cada projeto.

Uma situação para examinar com o Código

Imagine uma revisão de código em que um assistente de IA colocou uma regra de desconto diretamente na interface de checkout. O ponto de partida para a discussão é o texto do Canon X:

Layers must not harbor improper dependencies. Specifically, the Domain layer must remain pure and entirely oblivious to Infrastructure or Interface concerns. Dependencies must always point inwards.
Canon X · Article 10.2

Onde está definida a regra de desconto? Quais componentes dependem dela? Que decisão e evidência a revisão precisa registrar? Este é um exemplo didático para orientar a leitura do texto integral.

Textos prontos e selo de referência

Como usar o Código no seu projeto?

Para quem é?

Engenheiros, estudantes e equipes que usam assistentes de programação e querem discutir arquitetura, dívida cognitiva e responsabilidade sobre o código gerado.

Por onde começar?

Execute o checkout acima e acompanhe uma decisão do domínio até a interface. Depois leia o ADA preenchido e aplique as perguntas a uma mudança pequena no seu projeto.

O que já é automatizado?

O exemplo verifica sua política fictícia. O repositório também contém configurações e verificações demonstrativas. A conformidade de um sistema real depende de controles implementados e de revisão; o protocolo não certifica automaticamente todo código.

Quais resultados estão demonstrados?

O exemplo mostra separação de camadas e testes de fronteira. A eficácia do método contra dívida cognitiva ainda precisa ser avaliada. Consulte as fontes e os limites das evidências.
